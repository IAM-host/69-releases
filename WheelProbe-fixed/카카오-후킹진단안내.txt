카카오 후킹·메모리·시스템 API 진단 및 스택 클래스 상세판 — 2026-11-15

이번 추가는 관찰용입니다.
새 진단은 감지 결과·인자·예외·보고 객체·목록을 변경하거나 검사를 건너뛰지 않습니다.
기존 qf8 처리, 파일 경로 15개, Sentry 설정, 콜 감지·수락 코드는 그대로 유지합니다.

왜 새 로그가 필요한가
직전 로그의 hook(stack=3)는 카카오 보고 객체에 들어 있는 스택 클래스 항목 3개라는 뜻입니다.
기존 버전은 개수와 마커 힌트만 출력해 그 이름을 볼 수 없었습니다.
첨부 소스 z23의 해당 검사는 StackTraceElement.getClassName()만 저장합니다.
따라서 이번에는 원래 저장된 클래스명을 제한적으로 출력합니다. 메서드명이나 전체 호출 스택을 추정하지 않습니다.
별도로 현재 스레드의 스택을 다시 수집하지도 않습니다.

적용 및 로그 받기
1. E02.kt.txt 전체 코드로 기존 E02.kt를 교체하고 새 APK를 빌드·설치합니다.
2. 카카오를 강제 종료한 뒤 재실행합니다.
3. 직전과 같은 합의된 테스트 동작을 재현한 직후 아래 CMD 명령을 실행합니다.

cd /d "%LOCALAPPDATA%\Android\Sdk\platform-tools"
adb logcat -b all -d -t 10000 -v threadtime > "%USERPROFILE%\kakao-stack.txt" 2>&1
notepad "%USERPROFILE%\kakao-stack.txt"

메모장에서 KAKAO_DIAG: STACK_CLASS를 검색합니다.
예시 형식(아래 이름은 실제 감지 결과를 미리 단정한 것이 아닙니다):
KAKAO_DIAG: STACK_CLASS index=1 className=... resultChanged=false
KAKAO_DIAG: STACK_CLASSES total=3 logged=3 redacted=0 sampleTruncated=false resultChanged=false

total은 원래 보고 객체의 스택 클래스 항목 수입니다.
logged는 제한 조건에 맞아 출력한 클래스명 수, redacted는 표본 안에서 출력하지 않은 항목 수입니다.
index는 출력 순서이며 특정 후킹 대상이나 코드 오류 번호가 아닙니다.
최대 16개 항목만 확인하며, 범위를 넘으면 sampleTruncated=true가 됩니다.
알려진 프레임워크·모듈 패키지 또는 생성 클래스명이고 256자 이하의 클래스명 형식인 경우만 출력합니다.
원문 파일 경로·URL·토큰·메서드 서명·줄바꿈·형식에 맞지 않는 임의 문자열은 출력하지 않습니다.
호출 클래스명은 LSPosed 같은 공통 연결 부품 이름일 수 있으며, 이름만으로 고장 난 코드 위치를 뜻하지 않습니다.

기존 요약 로그
KAKAO_DIAG: REGISTERED target=il4.b ... mode=READ_ONLY liveExecution=UNVERIFIED
등록만 확인합니다. 원래 검사 함수가 실행될 때만 SIGNALS와 상세 클래스 로그가 나옵니다.
KAKAO_DIAG: SIGNALS status=... hook(stack=...,classes=...) memory(artifacts=...,foreign=...) api(native=...,missing=...) ...

status는 보고 객체의 detected/not_detected/unknown 값이며, 서버의 최종 허용 판정이 아닙니다.
hook.stack은 호출 기록의 후킹 신호, hook.classes는 Xposed 관련 클래스 신호 수입니다.
memory.artifacts/foreign은 후킹 모듈·외부 코드 매핑 신호 수입니다.
api.native/missing은 예상 밖 native 메서드 형태·API 누락 신호 수입니다.
markerHints는 목록별 앞 64개 항목에서 찾은 고정 라벨 힌트입니다.
NONE_IN_SAMPLE은 알려진 이름을 표본에서 찾지 못했다는 뜻이며 정상 보증이 아닙니다.
상세 클래스 로그의 16개 제한과 요약 힌트의 64개 제한은 서로 다릅니다.

오류와 한계
ORIGINAL_CHECK_FAILED는 원래 검사 함수의 예외, READ_FAILED는 진단 읽기 실패입니다.
UNAVAILABLE는 실제 APK의 클래스 구조가 첨부 소스와 맞지 않아 연결을 생략했다는 뜻입니다.
원래 결과·예외를 정상 판정으로 바꾸지 않습니다.
기존 코드의 cleared/bypassed 문구는 감지 해제 성공의 근거가 아닙니다.
현재 관찰한 결과와 서버가 내리는 최종 판정은 별개입니다.

검증
Android assembleDebug 성공.
상세 진단 포함 49개 + 기존 카카오 카드·수락·공통 87개 검사 통과.
허용 범위·형식·길이·16개 제한·원문 차단·결과와 예외 및 목록 보존을 검사했습니다.
새 상세 추출 함수와 추가 출력 호출 이외의 E02 코드는 이전과 바이트 단위로 동일합니다.
UTF-8 BOM 없음, CRLF 줄바꿈 유지.
실제 휴대폰·카카오 APK·서버에서의 새 버전 실행은 아직 검증하지 않았습니다.
