로지 D1·D2 적용 안내 — 2026-11-16

교체 파일은 아래 5개입니다. 각 TXT에는 해당 파일의 전체 내용만 들어 있습니다.

1. ModuleMain.kt.txt → app/src/main/java/com/example/wheelprobe/ModuleMain.kt
2. E05.kt.txt → app/src/main/java/com/example/wheelprobe/E05.kt
3. ConditionProvider.kt.txt → app/src/main/java/com/example/wheelprobe/ConditionProvider.kt
4. AndroidManifest.xml.txt → app/src/main/AndroidManifest.xml
5. scope.list.txt → app/src/main/resources/META-INF/xposed/scope.list

E01·E02·E04·E06은 이번 교체 대상이 아닙니다. 새로운 런타임 Kotlin 파일을 만들지 않았습니다. LogiPackageRoute도 E05 안에 포함돼 있습니다.

이번 변경
- D1(com.logisoft.Logi4)과 D2(com.logisoft.Logi5)가 기존 E05의 같은 콜 처리 경로를 사용합니다.
- 로딩된 실제 앱 패키지를 저장해서 D2에서 처리한 콜은 D2 화면을 앞으로 가져옵니다. 알 수 없는 패키지는 D1으로 추측하지 않습니다.
- 조건·GPS 전달 허용 목록, 패키지 조회와 LSPosed 기본 scope에 D2를 추가했습니다.
- 위도·경도 훅을 각각 설치하고, 하나의 등록이 실패해도 다른 쪽을 시도합니다. 실제 등록 개수를 별도로 기록합니다.
- 콜 파서, 조건 비교, 일반/탁송 분류, 수락 작업과 성공 확인 후 감지 OFF 로직은 기존과 같습니다.

GPS 변경의 정확한 범위
- 이번에 수정한 것은 좌표 훅의 독립 설치·부분 실패 처리와 D2로의 GPS 설정 전달입니다.
- 기존 코드가 찾는 모의 GPS 검사 클래스 이름 두 개는 제공된 D1/D2 APK에 없으며, 그 이름을 실제 감지 함수로 바꾸는 수정은 포함하지 않았습니다. 기존 선택 처리 구간과 관련 후커 본문은 유지했습니다.
- 따라서 모의 GPS 검사 대응까지 모두 복구됐다는 의미가 아닙니다.
- 로그의 coordinates registered=2/2는 두 좌표 훅의 등록 성공을 뜻합니다. 실제 좌표 적용·서버 송신 성공을 뜻하지 않습니다.
- legacy target unavailable 로그가 함께 나와도 좌표 훅 등록 결과는 별도로 확인해야 합니다.

적용 순서
1. 위 5개 파일을 각 경로의 기존 파일에 전체 덮어쓰기합니다. 코드 블록 표시나 설명 문장을 파일에 붙이지 않습니다.
2. Android Studio에서 APK를 다시 빌드·설치합니다.
3. LSPosed의 EUNORA 적용 범위에서 사용할 로지D1·로지D2가 각각 체크돼 있는지 확인합니다.
4. 실행 중인 로지 앱을 강제 종료한 뒤 다시 실행합니다. EUNORA에서 조건·GPS 설정을 전달합니다.

확인할 시작 로그
- EUNORA: Logi package loaded package=com.logisoft.Logi4
- EUNORA: Logi package loaded package=com.logisoft.Logi5
- LOGI_GPS: coordinates registered=2/2 package=해당_패키지 liveExecution=UNVERIFIED

검증
- 실제 Android assembleDebug 성공. 생성 APK의 scope와 Manifest에도 D1·D2 포함을 확인했습니다.
- 실제 E05 라우팅·좌표 훅 설치 코드로 57개 검사 통과.
- 기존 로지 데이터·수락 상태 검사 131개 통과.
- 전달한 5개 TXT는 빌드한 해당 소스와 바이트가 같습니다.
- APK를 휴대폰에 설치하거나 실제 콜·좌표 전송을 실행한 것은 아닙니다.
