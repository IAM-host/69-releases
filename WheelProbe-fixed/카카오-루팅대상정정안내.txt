카카오 기존 루팅 처리 + Sentry 진단 테스트 설정 — 2026-11-15

교체
E02.kt.txt 전체 코드로 기존 E02.kt만 교체합니다.
새 런타임 .kt 파일을 따로 추가하지 않습니다.

이번 추가: 명령 실행·설치 앱 조회가 있던 확인된 경로
첨부 소스에서 이 두 검사는 Sentry의 진단용 RootChecker에 들어 있습니다.
명령: /system/xbin/which su
조회: 루팅 관리 앱 6개 패키지
업무용 ec4/qf8 루팅 검사와 별개의 진단 수집 경로입니다.

이 수정은 SDK 공개 옵션 setEnableRootCheck(false)를 사용합니다.
새 r0(Context, SentryAndroidOptions) 생성 직전에 옵션을 설정하므로,
첨부 소스의 r0가 이 진단용 RootChecker를 생성·실행하는 분기에 들어가지 않게 합니다.
따라서 그 진단 안에 있던 명령 실행·루팅 관리 앱 조회도 수행하지 않는 테스트 설정입니다.
시스템 전체 Runtime.exec 또는 PackageManager 조회 결과를 변경하는 구현은 아닙니다.

의미와 범위
별도의 rooted=false 판정을 만들어 넣지 않습니다.
첨부 소스에서는 진단을 수행하지 않으면 새 OS 정보의 rooted 필드가 null로 남아 직렬화되지 않습니다.
이미 만들어진 캐시·기존 이벤트·사용자 정의 컨텍스트의 과거 값까지 지우지는 않습니다.
카카오의 모든 앱 조회나 다른 SDK의 독립적인 검사까지 비활성화한다는 의미는 아닙니다.
Play Integrity 토큰이나 서버 검증은 변경하지 않았습니다.

설치·실행 순서
1. E02.kt 교체 후 새 APK를 빌드·설치합니다.
2. 카카오 앱을 강제 종료한 뒤 다시 실행합니다. 화면 전환만으로는 부족합니다.
3. 아래 로그를 확인합니다.

KAKAO: Sentry root diagnostic test config hook installed ... coldStartRequired=true
KAKAO: Sentry root diagnostic test config settingApplied=true requestedEnableRootCheck=false ...

첫 줄은 생성자 훅 등록만 확인합니다.
settingApplied=true는 실제로 SDK setter 호출 뒤 getter가 false를 반환한 것을 확인했다는 뜻입니다.
카카오 서버의 최종 보안 판정이 통과됐다는 뜻은 아닙니다.
NOT_APPLIED reason=MISSING_CONFIGURATION은 설정 객체를 얻지 못했다는 뜻입니다.
APPLY_UNCONFIRMED는 설정 중 예외로 적용 여부를 확정하지 못했다는 뜻입니다.
UNAVAILABLE는 첨부 소스와 클래스·메서드·필드 구조가 맞지 않아 연결을 생략했다는 뜻입니다.
오류 로그에는 토큰·사용자 ID·예외 메시지를 넣지 않습니다.

기존 수정 보존
qf8(ht7, boolean) 정확한 생성자와 a:ht7, b:boolean 필드 검증을 유지합니다.
KakaoRootingStatusHooker의 기존 결과 처리 본문을 유지합니다.
카카오 전용 File.exists 경로 15개와 기존 결과 처리를 유지합니다.
T맵이 공유하는 기존 KakaoRootPathHooker 및 콜 감지·수락·GPS 코드도 그대로입니다.
이 추가는 SDK 설정 연결 호출 1줄과 새 SDK 설정 구간에 한정됩니다.
