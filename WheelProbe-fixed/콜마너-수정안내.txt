콜마너 진단판 안내

이번 교체 파일: E04.kt.txt 한 개
E04.kt.txt의 전체 내용을 app/src/main/java/com/example/wheelprobe/E04.kt에 덮어씁니다.
기존 E02.kt·E05.kt와 다른 파일은 이번 교체 대상이 아닙니다. 별도 .kt 파일은 필요하지 않습니다.

이번 판의 목적
- 빌드 표시: 20261111.1
- 콜 감지가 안 된다는 현상의 실제 원인은 아직 확정하지 않았습니다. 이번 파일은 감지·조건 매칭·수락 중 어느 단계에서 멈추는지 로그로 확인하기 위한 진단판입니다.
- 새로 받은 자료의 앱 버전은 6.3.9.4이고, 감지·수락 핵심 파일 21개는 이전 자료와 같습니다.
- 시작 시 데이터 처리 자체 검사를 추가하고, 실제 콜 이벤트·조건 수신·화면 준비 상태·콜의 목적지/금액/픽업 거리·수락 요청과 결과를 기록합니다.
- 기존 조건 매칭과 수락 동작을 유지합니다. 이 파일을 적용했다는 것만으로 보고된 감지 누락이 해결됐다고 판단하지 않습니다.

설치 및 로그 수집
1. E04.kt 전체 코드를 교체한 뒤 내 앱의 새 APK를 빌드하고 설치합니다.
2. PC CMD에서 다음 명령으로 로그 수집을 시작합니다.
   adb logcat -v time | findstr /I CALLMANER > callmaner-log.txt
3. 안드로이드 설정에서 콜마너를 강제 종료한 뒤 다시 실행합니다.
4. EUNORA 감지를 ON으로 켜고 문제가 발생한 상황을 다시 확인합니다.
5. CMD에서 Ctrl+C로 수집을 끝내고 callmaner-log.txt를 확인합니다.

확인할 로그
- BUILD=20261111.1 및 DATA_SELF_TEST_OK: 새 코드 실행과 시작 시 자체 검사
- DATA_HOOK_FIRED: 콜 데이터 감지 지점 실행
- CONDITIONS 및 SCAN_BLOCKED: 조건 수신 상태와 진행을 막은 이유
- CALL_DATA: 실제 목적지·금액·픽업 거리와 원본 금액 표시
- REQUEST_OBSERVED 및 ACCEPT_: 수락 요청 연결과 서버 결과

검증 범위
- 로컬 assembleDebug 빌드와 데이터·상태 회귀 검사 170개, 네이티브 ICU 검사 14개를 통과했습니다.
- 전체 TXT는 검사한 실제 소스와 바이트가 같으며 CRLF, UTF-8 BOM 없음 형식입니다.
- 로컬 빌드·회귀·호스트 ICU 검사와 실제 단말 동작은 구분됩니다. 실제 감지 누락의 원인과 최종 배차 수락 성공은 아직 검증하지 못했습니다.
