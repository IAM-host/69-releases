# EUNORA 미사용 코드 정리본 · 2026-11-19

최근 전달한 E02~E06(최종 T맵 E03 포함)을 기준으로 정리했습니다. 이전 수정본을 적용하지 않았다면 이번 전체 파일에 이전 수정도 포함되어 있습니다.

## 적용

1. ZIP을 새 폴더에 압축 해제합니다. Android Studio에서 진행 중인 파일 편집은 먼저 저장하세요.
2. `Apply-EUNORA.cmd`를 실행하고, `app` 폴더와 `gradlew`가 있는 **WheelProbe 프로젝트 폴더**를 입력합니다. E02 파일 자체를 선택하는 것이 아닙니다.
3. 기존 파일은 프로젝트의 `EUNORA-backup-날짜시간` 폴더에 백업됩니다. E02~E06 전체 파일을 적용하고, 확인된 미사용 파일 4개를 삭제합니다.
4. Android Studio에서 다시 빌드합니다. 이 묶음에는 APK가 없으며, 휴대폰 설치나 앱 실행은 자동으로 하지 않습니다.

다른 수정 내용이 있는 파일은 덮어쓰지 않고 중단합니다. 이 경우 강제로 적용하지 말고 현재 프로젝트를 기준으로 병합해야 합니다. 같은 정리본을 다시 실행하면 이미 적용된 파일은 건너뜁니다. 자동 백업에는 적용 전에 바뀌거나 삭제될 파일만 들어갑니다.

수동 적용도 가능합니다. E02.kt~E06.kt를 `app/src/main/java/com/example/wheelprobe/`에 교체하고 `DELETIONS.txt`의 네 파일을 삭제하세요. E02.txt~E06.txt는 같은 전체 코드를 메모장에서 열기 위한 파일입니다. TXT를 프로젝트에 추가하지 마세요. E05는 이번 정리에서 변경하지 않았으며 최신 세트를 함께 전달하기 위해 포함했습니다.

## 정리 내용

- E02: 호출 없는 설치 함수 4개, 미등록 Hooker 4개, 쓰지 않는 진단 출력 함수 묶음 제거.
- E03: 미사용 K0ConstructorHooker 호환 클래스 제거.
- E04: 호출 없는 호환 설치 함수 3개 제거.
- E06: 연결되지 않은 구형 일반 목록·StaticObj 처리 묶음 제거. 현재 자동배차 오버레이 처리 유지.
- 고아 파일: AutoClickService.kt, ExecutionClient.kt, 접근성 XML, 중첩 경로 ErrorReporter.kt 삭제.

실제 훅 등록 목록과 남은 처리 코드는 바이트 단위로 동일합니다. ModuleMain, E01, E05, 조건 전달, Manifest, scope, 빌드 설정은 변경하지 않았습니다. L 프로그램도 변경하지 않았습니다.

## 검증

Debug·Release Kotlin 컴파일 모두 통과했습니다. 수정된 4개 파일에서는 미사용 코드 384줄만 삭제했고, 고아 파일 4개를 추가로 제거했습니다. 나머지 66개 파일은 동일합니다. 기존 E02의 nullable 경고는 남아 있습니다. 휴대폰에서 실제 콜 수신·수락 동작은 별도로 확인해야 합니다.

`cleanup.patch`는 직전 최신 E02·E03·E04·E06의 변경 내역이고, 삭제 파일 목록은 `DELETIONS.txt`에 있습니다. `VALIDATION.json`과 `compile.log`에 검증 결과가 있습니다. 적용 도구는 PowerShell 7.5.4 Linux에서 검증했으며 실제 Windows 실행은 확인하지 못했습니다. Windows 적용 도구는 백업과 파일 교체를 위한 것으로 EUNORA 실행 코드에 추가되지 않습니다.
