# EUNORA 로지 D1 21.55 네이티브 연결 · 2026-11-25

앞서 수정한 콜 감지·수락·Java 보고서 대응에, 제공된 로지 D1 21.55/versionCode632 ARM64 라이브러리의 확인된 루팅 판단 함수 연결을 추가했습니다. 지도 초기화·암호화·인증 흐름은 계속 실행하며, 해당 함수도 원래 처리를 먼저 실행한 뒤 결과를 처리합니다. 설치 앱 조회·EUNORA 숨김과 SET 6개 화면 작업은 포함하지 않았습니다.

## 적용

1. ZIP을 새 폴더에 압축 해제하고 Android Studio의 진행 중인 편집을 저장합니다.
2. Apply-EUNORA-Native.cmd를 실행합니다.
3. app 폴더와 gradlew가 있는 WheelProbe 프로젝트 폴더 경로를 입력합니다.
4. 기존 파일은 EUNORA-native-backup-날짜시간 폴더에 백업됩니다. E05·ModuleMain·ProGuard 설정을 적용하고, 네이티브 부품·등록 파일·재빌드용 소스를 추가합니다.
5. Android Studio에서 새 APK를 빌드·설치하고 로지를 강제 종료한 뒤 다시 실행합니다. 새 모듈 등록이 반영되지 않으면 휴대폰을 재부팅한 뒤 확인합니다.

이번에는 ZIP의 추가 파일까지 함께 적용해야 합니다. E05.txt·ModuleMain.txt는 같은 전체 코드를 메모장에서 보기 위한 파일입니다. 텍스트 두 개만 교체하는 것으로 네이티브 등록까지 적용되지는 않습니다.

적용 도구는 알려진 원본과 일치하는 파일만 바꾸며, 다른 수정 내용이 있으면 쓰기 전에 중단합니다. 이때 강제로 덮어쓰지 말고 현재 소스에 병합해야 합니다. 정상 적용 후 다시 실행하면 변경 없이 끝납니다. 적용 도구는 Linux PowerShell에서 검증했으며 실제 Windows 실행은 미확인입니다.

## 적용 범위

- 제공된 D1 패키지·메인 프로세스·원본 APK SHA-256·ARM64 대상 라이브러리 SHA-256이 모두 일치할 때만 부품을 불러옵니다.
- 네이티브에서도 ELF Build ID·실제 심볼·원본 함수 명령을 추가로 확인합니다. 다른 버전·D2·다른 ABI에는 이 네이티브 처리를 적용하지 않습니다.
- 등록 대기와 실제 설치 성공 상태를 구분합니다. 이미 대상 라이브러리가 먼저 로드됐거나 프레임워크가 지원하지 않으면 처리 완료로 표시하지 않습니다.
- 원래 SDK 초기화, 네이티브 인증·서명·버전 응답, 다른 검사와 설치 앱 목록 조회는 유지됩니다. 모든 보안 검사를 처리했다는 의미는 아닙니다.
- 기존 E05 전체 코드와 GPS·수락 처리 부분은 유지하고 연결부를 덧붙였습니다. ModuleMain은 초기 연결 호출과 프로세스 이름 저장만 추가했습니다. 기존 Gradle·Manifest·조건·UI 파일은 변경하지 않았습니다.

네이티브 부품은 일반 JNI 라이브러리로 APK에 포함됩니다. C 소스·헤더와 tools/build_logi_native.py도 함께 제공하며, 네이티브 부품을 직접 재빌드할 때만 해당 스크립트와 Android NDK가 필요합니다.

## 휴대폰 로그 확인

USB 연결 후 platform-tools CMD에서 아래 명령을 실행하고 로지를 다시 켭니다. 로그인 후 콜 목록 화면까지 열어 확인할 수 있으며, 콜이 새로 뜰 때까지 기다릴 필요는 없습니다.

```cmd
adb logcat -v time -s EUNORA_LOGI_NATIVE
```

- WAIT_TARGET: 부품 연결을 준비했고 대상 라이브러리 로드를 기다리는 상태입니다. 아직 설치 성공을 뜻하지 않습니다.
- Verified native rooting leaf hook active: 확인한 함수에 연결됐습니다.
- Verified native rooting result normalized: 원래 판정이 true였던 호출을 처리했습니다. 원래 false라면 이 메시지는 없어도 됩니다.
- WAIT_FRAMEWORK / LATE_UNSUPPORTED / TARGET_REJECTED 등: 해당 실행에서는 정상 적용이 확인되지 않은 상태입니다. 로그를 기준으로 확인해야 합니다.

로그 메시지는 연결 상태를 보여줍니다. 실제 서버 수신·판정·서비스 허용을 증명하는 메시지는 아닙니다.

## 검증

Debug·Release 컴파일, Release 린트·R8 난독화·APK 패키징을 통과했습니다. APK에 네이티브 등록 파일과 4개 ABI 부품이 들어 있는지, 압축 없이 저장되는지, 16KB 정렬과 JNI 이름이 유지되는지도 확인했습니다. 39개 C 검사, 35개 Java 연결 검사, 실제 ELF를 데이터로 사용하는 독립 검증을 수행했습니다. 실제 Android 기기의 프레임워크 연결과 서버 동작은 아직 검증하지 못했습니다.
