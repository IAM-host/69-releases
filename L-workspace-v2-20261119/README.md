# L — EUNORA 작업 공간

L은 APK와 EUNORA 프로젝트를 점검하고, 확인한 대상의 코드 사본과 빌드 결과를 정리하는 Windows용 개발 도구입니다. 화면은 네 개의 작업 영역으로 구성하며, 기본 화면의 설명 문구·입력 예시·단계 장식을 제거했습니다. AI 모델 연결은 포함하지 않습니다.

## 기존 L에서 업데이트

1. L을 종료하고 기존 폴더를 백업합니다.
2. 새 ZIP 안의 프로그램 파일을 **기존 L 폴더에 덮어씁니다.** `main.py`만 교체하면 안 됩니다.
3. `run_L.bat`를 실행합니다. 기존 REA 설치가 정상이라면 다시 설치할 필요가 없습니다.
4. EXE로 사용한다면 `build_L.bat`로 새 `L.exe`를 만든 뒤 실행합니다.

전달 ZIP에는 `.venv`, 설치된 `tools`, `rea_settings.json`, 사용자 APK·로그·생성본을 넣지 않습니다. 기존 폴더를 삭제하지 않아야 설치와 작업 데이터를 이어서 사용할 수 있습니다. 별도 폴더로 옮기는 경우 설정의 도구 경로를 확인하세요.

## 처음 실행

- Python 3.10 이상을 설치하고 `run_L.bat`를 실행합니다. 첫 실행은 이 폴더의 `.venv`에 PySide6를 설치하며 인터넷이 필요합니다.
- REA 분석에는 지원되는 Node.js와 전체 JDK 17 이상이 필요합니다. **Node.js 24 LTS와 JDK 21**을 권장합니다. Android Studio의 `jbr`도 `jdk.compiler`가 있으면 사용할 수 있습니다.
- `setup_rea.bat`를 실행해 REA와 전용 headless 분석 도구를 설치합니다. Node/JDK 자체는 자동 설치하지 않습니다.
- USB 추출과 기기 로그에는 Android SDK `platform-tools`의 `adb.exe`가 필요합니다.

지원 Node 버전은 22.23.4 이상인 22.x, 24.22.1 이상인 24.x, 또는 26.12.1 이상입니다. 설치 버전과 파일 해시 검사는 기존 방식으로 유지합니다. 경로를 자동으로 찾지 못하면 다음처럼 지정할 수 있습니다.

```cmd
.venv\Scripts\python.exe install_rea.py --node "C:\Program Files\nodejs\node.exe" --java-home "C:\Program Files\Android\Android Studio\jbr"
```

## 기본 작업 흐름

**APK·EUNORA 선택 → 점검 → 결과 확인 → 코드 생성 → 빌드 검사 → 기기 로그 확인**

### 작업 공간

대상 APK와 EUNORA 프로젝트 폴더를 한곳에서 선택합니다. 프로젝트 안의 `ModuleMain.kt`를 지정하는 기존 입력도 지원합니다. L이 점검하는 기준은 선택한 프로젝트의 실제 파일입니다. 별도로 받은 EUNORA 수정본은 먼저 그 프로젝트에 적용해야 합니다.

- **기존 훅 점검**은 선택한 앱의 E파일에서 정적으로 해석 가능한 클래스·메서드 이름을 읽고 APK와 대조합니다. 패키지로 카카오(E02), T맵(E03), 콜마너1·2(E04), 로지D1·D2(E05), 아이드라이브(E06)를 구분합니다.
- **보안 점검**은 실제 DEX 문자열과 호출 위치로 검사 후보를 찾고, REA와 DEX 원형을 대조합니다. 일반적인 `RootActivity` 같은 이름만으로 검사 함수라고 확정하지 않습니다.
- **코드 생성**은 현재 점검 결과에서 지원되는 대상을 선택해 진행합니다. 호출 관찰은 인자·반환값·예외를 보존합니다. 보안 후보의 Boolean 결과 변경이나 void 본문 실행 생략은 해당 대상이 지원하는 경우에만 선택합니다.
- **빌드 검사**는 원본 프로젝트를 별도 폴더에 복사하고 생성본만 적용해 `:app:compileDebugKotlin`을 실행합니다. 원본 Android 코드는 직접 덮어쓰지 않습니다.

점검·생성 후 입력 APK나 원본 소스가 바뀌면 새 근거로 다시 진행해야 합니다. 결과 영역에서 표·원문·생성 파일을 전환해 확인합니다. USB APK 추출은 기기 로그 화면으로 옮겼습니다. 생성본에는 전체 E파일과 ModuleMain 사본, TXT, diff, manifest가 포함됩니다.

클래스 발견이나 컴파일 통과는 기기 동작 확인과 다릅니다. 정적 점검은 함수의 전체 업무 의미를 이해하지 않으며, 새로운 콜 수락 로직을 스스로 추론해 작성하는 기능도 아닙니다. DTO·생성자·지원하지 않는 반환형은 현재 결과 변경 템플릿의 범위 밖입니다. 서버 판정·서명·무결성 토큰 관련 대상은 결과 변경 후보에서 제외합니다.

### 기기 로그

연결된 Android 기기에서 로그를 시작하고 필요한 구간을 캡처해 저장합니다. 앱 태그를 지정하면 이후 기록을 구분할 수 있습니다. 새 모듈 설치와 LSPosed 적용, 대상 앱의 완전 종료·재실행 후 실제 호출 로그를 확인합니다. 관찰용 로그 접두사는 `L_OBSERVER`, 보안 테스트용은 `L_SECURITY_TEST`입니다.

### 기록

저장한 기기 캡처를 앱별로 찾아 원문·요약·키워드 매칭을 확인합니다. 기존 `sessions`와 `hooks.json`은 계속 읽습니다. 업데이트가 기존 파일을 덮어쓰거나 지우지 않습니다.

### 설정

REA와 JDK 경로, 사전 검사 등 도구 설정을 관리합니다. 수동 REA 클래스·메서드·참조 분석, 구조·심화 분석, JADX XREF와 APK 비교는 상세 분석이 필요할 때 사용합니다. 분석 엔진은 유지하되 기본 작업 화면에서 여러 버튼을 고르던 과정을 줄였습니다.

## 제거한 구형 흐름

- 독립된 후보군 편집 화면과 구형 훅 지도 화면
- 로그의 미검증 클래스 후보로 ModuleMain 문자열을 치환하던 `전체코드 만들기/복사`
- 구형 지도 전용 지식 파일 다시 읽기와 관련 추측·치환 코드

기존 `eunora_hooks.json`은 구형 지도 설정이므로 새 작업 흐름에서 사용하지 않습니다. 사용자 파일 자체는 삭제하지 않습니다. 프로젝트와 APK 근거에 맞춰 사본을 만드는 현재 생성기, 원본 보존·해시 확인·빌드 검사는 유지합니다.

## 빌드와 파일 위치

Windows에서 `build_L.bat`를 실행하면 PyInstaller가 `dist\L.exe`를 만들고 이 소스 폴더의 `L.exe`로 복사합니다. **전달물은 소스이며 Windows EXE를 포함하지 않습니다.** Windows EXE 실행과 실제 휴대폰 연결은 해당 환경에서 별도로 확인해야 합니다.

실행 파일 옆에 `tools`, `rea_settings.json`, `sessions`, `apks`, `rea_results`, `eunora_audits`, `security_audits`, `generated_hooks`가 저장됩니다. 소스로 실행하면 `main.py` 옆을 사용하고, `L_APP_DATA_DIR`로 별도 데이터 폴더를 지정할 수 있습니다.

Windows 빌드 검사는 짧은 ASCII 경로를 사용합니다. 기본 `%LOCALAPPDATA%\L-build`가 적합하지 않으면 다른 쓰기 가능한 영문 경로를 찾으며, `L_BUILD_DIR`로 지정할 수도 있습니다. 원본 프로젝트의 Gradle 경로 검사 설정은 변경하지 않습니다. 빌드 로그와 결과 JSON은 생성본의 `build_checks`에 보관합니다.

## 검증

`run_tests.bat` 또는 개발 환경에서 `python -m pytest -q`로 검사합니다. Qt 검사는 offscreen으로 실행할 수 있습니다. 검증 결과와 전달 파일 해시는 별도 검증 기록에 명시합니다. 실제 REA·Android SDK·의존성이 필요한 작업은 설치 환경의 영향을 받습니다.

APK 분석 원문·기기 로그·생성 코드에는 사용자 데이터가 포함될 수 있습니다. 배포 ZIP에는 사용자 데이터와 설치된 외부 도구를 넣지 않습니다.
