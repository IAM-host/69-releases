# L의 작업 방향

L은 EUNORA 개발과 유지보수를 위한 PC 작업 공간입니다. 휴대폰에서는 EUNORA가 콜을 감지하고 처리하고, L에서는 APK·기존 프로젝트·검사 결과·코드 사본·빌드 결과를 연결합니다.

## 하나의 기본 흐름

**APK와 EUNORA 선택 → 기존 훅 또는 보안 점검 → 대상 확인 → 코드 사본 생성 → 빌드 검사 → 기기 로그 확인**

앱 종류와 프로젝트 입력은 한곳에서 관리합니다. 점검에서 얻은 근거를 생성과 빌드까지 이어 사용하고, APK나 소스가 바뀌면 기존 결과를 그대로 재사용하지 않습니다. 클래스 발견·컴파일 성공·기기 실행 확인은 서로 다른 상태로 표시합니다.

화면은 작업 공간, 기기 로그, 기록, 설정의 네 영역으로 나눕니다. 기본 화면에는 지금 진행할 작업과 결과를 먼저 보여줍니다. 수동 클래스 검색·메서드 분석·XREF·원문 JSON과 diff는 필요할 때 상세 도구에서 확인합니다.

## 이번 정리의 범위

- 구형 ModuleMain 문자열 추측·치환 흐름과 독립 후보군·훅 지도 UI를 제거합니다.
- 현재 E02~E06 파일을 읽는 자동 점검과 근거 기반 사본 생성기를 기본 흐름으로 사용합니다.
- REA·DEX 분석, 사용자 원본 보존, 해시 확인, 격리된 빌드 검사는 유지합니다.
- 기기 캡처와 기존 작업 기록을 보존합니다. 기존 사용자 설정·도구·APK를 프로그램 업데이트에 덮어쓰지 않습니다.
- AI 모델을 연결하거나 분석·생성 엔진의 의미 해석 능력을 새로 추가하는 작업은 이번 범위가 아닙니다.

## 현재 자동화가 하는 일

패키지·소스 배치·직접 명시된 클래스와 메서드·DEX 원형을 규칙으로 대조하고, 지원하는 메서드에 정해진 Kotlin 템플릿을 적용합니다. 원본 파일을 바꾸는 대신 전체 코드와 TXT·변경 내역을 별도 폴더에 생성합니다.

관찰용 코드는 호출 정보를 기록하며 원래 인자·결과·예외를 보존합니다. 보안 점검에서 원형과 근거가 확인된 후보에는 지원되는 Boolean 결과 변경 또는 void 본문 실행 생략 모드를 선택할 수 있습니다. 동작과 지원 범위는 생성 전에 표시합니다.

## 별도 개발이 필요한 일

업데이트 전후의 구조가 달라진 대상을 의미로 매칭하는 일, 새로운 콜 수락 로직 작성, 조건 판정 전체 해석과 기기 로그의 자동 원인 진단은 추가 개발 영역입니다. 새로 발견한 함수의 이름·원형만으로 역할이 맞다고 판단하면 안 됩니다.

실제 APK에서 호출 경로와 결과 사용 방식을 확인한 뒤 규칙을 추가하고, 사본의 컴파일과 기기 실행을 각각 검증해야 합니다. 네이티브·동적 로딩·서버 판정·Play Integrity 전체는 현재 점검만으로 확인되지 않습니다.

## 화면 정리 2차

기본 화면은 파일 입력과 실행 도구, 결과 표에 집중합니다. 안내 문단과 입력 예시, 단계 장식은 제거하고 USB 추출은 기기 로그 화면에 둡니다. 분석 결과의 실제 설명과 오류 정보는 유지합니다.
