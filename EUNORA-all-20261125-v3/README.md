# EUNORA 통합 수정본 v3 · 2026-11-25

이전에 전달한 미사용 코드 정리와 최신 로지 D1 21.55 수정·네이티브 연결을 함께 포함했습니다. 이전 정리 ZIP과 로지 ZIP을 먼저 적용할 필요 없이 이 통합본을 한 번 적용하면 됩니다.

이번 v3는 첨부해 주신 E02~E06·ModuleMain·ProGuard 설정 7개를 모두 확인하고, 그 실제 파일들을 함께 사용해 통합 적용을 검증했습니다. E03·E04·E05·E06의 들여쓰기 차이만 확인됐으며, 해당 파일의 정확한 SHA-256을 지원 목록에 반영했습니다. E02·ModuleMain·ProGuard 설정은 이미 지원하는 원본과 동일했습니다. 앱에 적용하는 15개 파일과 적용 도구 자체는 이전 통합본과 동일합니다.

## 적용 방법

1. 이 ZIP을 OneDrive 밖의 `C:\EUNORA-update-v3` 같은 새 폴더에 압축 해제합니다. Android Studio에서 편집 중인 파일을 먼저 저장하세요.
2. `Apply-EUNORA-All.cmd`를 실행합니다.
3. `app` 폴더와 `gradlew`가 있는 **WheelProbe 프로젝트 폴더** 경로를 입력합니다. APK나 E02 파일 자체를 선택하는 것이 아닙니다.
4. 적용 도구가 바뀌거나 삭제될 기존 파일을 `EUNORA-all-backup-날짜시간` 폴더에 백업하고, 파일 교체·추가와 확인된 미사용 파일 삭제를 수행합니다.
5. Android Studio에서 APK를 빌드·설치하고 로지를 강제 종료한 뒤 다시 실행합니다. 새 네이티브 등록이 반영되지 않으면 휴대폰을 재부팅해서 확인합니다.

CMD는 PC에서 파일을 적용하는 도구입니다. 휴대폰 앱을 실행하거나 APK를 자동 설치하지 않으며, 앱을 사용할 때마다 실행할 필요도 없습니다.

## 함께 들어 있는 변경

- **E02·E03·E04·E06:** 이전에 정리한 미사용 설치 함수·호환 클래스·연결되지 않은 구형 처리 코드 제거. 기존에 전달한 각 앱 수정도 포함한 전체 파일입니다.
- **E05:** 최신 로지 D1 콜 감지·수락·Java 보고서 대응과 네이티브 연결을 포함합니다. 이전 정리본의 오래된 E05로 되돌리지 않습니다.
- **ModuleMain·ProGuard 설정:** 네이티브 초기 연결 호출과 JNI 이름 유지 설정을 추가했습니다.
- **네이티브 추가 파일:** 등록 파일, 4개 ABI의 자체 부품 `.so`, C 소스·헤더, 선택적인 재빌드 스크립트입니다. 일반 APK 빌드에는 함께 제공한 부품을 사용하며, 직접 부품을 재빌드할 때만 Android NDK가 필요합니다.
- **미사용 파일 4개 삭제:** `AutoClickService.kt`, `ExecutionClient.kt`, 사용하지 않는 접근성 XML, 잘못 중첩된 경로의 `ErrorReporter.kt`입니다. 정확한 경로는 `DELETIONS.txt`에 있습니다. 알려진 내용과 일치할 때만 백업 후 삭제합니다.

총 15개 파일을 교체·추가하고, 미사용 파일 4개를 정리합니다. UI·SET 구성·GPS 설정 화면·L 프로그램은 이번 통합에서 바꾸지 않았습니다. 대리·탁송 SET을 각각 3개로 나누는 화면 작업은 포함하지 않았습니다.

`E02.txt`~`E06.txt`와 `ModuleMain.txt`는 같은 전체 코드를 메모장에서 보기 위한 파일입니다. **TXT 여섯 개만 교체하면 네이티브 등록·추가 파일·미사용 파일 삭제가 반영되지 않습니다.** 적용 도구를 사용하거나 `update-manifest.json`에 나열한 전체 파일과 삭제 목록을 함께 반영하세요. TXT를 Android 소스 폴더에 추가하지 마세요.

## 적용 도구의 확인

이전에 제공된 원본·수정본과 일치하는 파일만 바꾸며, 다른 편집 내용이 있으면 쓰기 전에 중단합니다. 이때 강제로 덮어쓰지 말고 현재 소스를 기준으로 병합해야 합니다. 적용 완료 상태에서 다시 실행하면 파일을 변경하지 않습니다. 적용 중 오류가 발생하면 변경한 기존 파일과 삭제 파일을 백업에서 복원하고, 해당 실행이 만든 새 파일을 제거합니다.

적용 도구는 Linux PowerShell에서 검증했습니다. 실제 Windows PowerShell 실행은 아직 확인하지 못했습니다.

## 검증과 로지 적용 범위

이 묶음의 15개 적용 파일은 Debug·Release 컴파일, Release 린트·R8·APK 패키징을 통과한 최종 프로젝트 파일과 바이트 단위로 동일합니다. 이전 정리에서 삭제한 네 파일도 해당 프로젝트에 존재하지 않습니다. `VALIDATION.json`, `APPLY-INTEGRATION.json`, `BUILD.log`에 검증 결과가 있습니다.

네이티브 처리는 제공된 **로지 D1 21.55/versionCode 632의 메인 프로세스·APK·ARM64 라이브러리**가 일치할 때만 확인된 루팅 판단 함수에 적용합니다. D2·다른 버전·다른 ABI에 같은 처리가 적용된다고 보장하지 않습니다. 원래 SDK 초기화·암호화·인증과 해당 함수의 원래 실행은 유지합니다. 설치 앱 조회·EUNORA 숨김과 다른 모든 보안 검사 처리는 포함하지 않았습니다. 실제 Android 기기에서의 프레임워크 연결·콜 수신·서버 동작은 별도로 확인해야 합니다.

USB 연결 후 platform-tools CMD에서 다음 명령을 실행하고 로지를 켜면 네이티브 연결 상태를 볼 수 있습니다.

```cmd
adb logcat -v time -s EUNORA_LOGI_NATIVE
```

- `WAIT_TARGET`: 대상 라이브러리 로드를 기다리는 상태입니다.
- `Verified native rooting leaf hook active`: 확인한 함수에 연결됐습니다.
- `Verified native rooting result normalized`: 원래 판정이 true였던 호출을 처리했습니다. 원래 false이면 이 메시지가 없어도 됩니다.

연결 로그는 서버의 허용 여부를 증명하지 않습니다. 이 ZIP에는 설치용 APK·서명 키·로지 APK·대상 SDK 라이브러리가 없으며, 본인 프로젝트에서 기존 방식으로 서명·빌드해 설치해야 합니다.
