# EUNORA 대리·탁송 SET 분리 통합본 — 2026-11-29

대리 SET1·2·3과 탁송 SET1·2·3을 각각 저장하고 매칭하도록 변경했습니다. 기존 카카오3.15·T맵177·로지·콜마너 수정도 포함한 누적 적용본입니다.

## 사용 방식

- 화면을 좌우로 넘기면 대리/탁송의 SET3개씩을 봅니다. 페이지 이동은 보기만 바꾸며, 감지·업종 선택·저장값을 변경하지 않습니다.
- 상단 대리/탁송의 밝은 표시는 기존처럼 감지 종류의 ON 상태입니다. 둘 다 밝으면 두 종류를 함께 감지합니다. 적어도 하나는 켜져 있어야 합니다.
- 꺼진 종류를 누르면 켜지면서 해당 SET 페이지가 열립니다. 켜진 종류를 누르면 꺼지며, 보고 있던 종류를 끄면 다른 페이지를 보여 줍니다. 둘 다 켜 놓고 설정만 살펴보려면 좌우로 넘깁니다.
- 감지 ON/OFF는 하나입니다. GPS도 두 종류가 공통으로 사용합니다. 탁송의 오늘/내일 설정은 유지합니다.
- 각 SET의 체크·단어·제외 단어·금액·거리를 따로 저장합니다. 종류를 꺼도 그 종류의 저장값과 체크는 남습니다. 감지 시작 여부는 현재 켜진 종류의 유효한 SET을 기준으로 판단합니다.
- 작은 화면에서는 위아래로 스크롤해 아래 SET과 저장 버튼까지 볼 수 있습니다. 가로 넘김과 세로 스크롤은 방향을 구분합니다.

## 기존 설정 이동

| 기존 설정 | 새 위치 |
| --- | --- |
| 대리 SET1 | 대리 SET1 |
| 대리 SET2 | 대리 SET2 |
| 탁송 SET3 | 탁송 SET1 |
| 새로 생긴 칸 | 대리 SET3·탁송 SET2·3, 빈 값/체크 해제로 시작 |

설정과 단어 입력 기록을 한 번만 이동합니다. 기존 키는 백업으로 남기고, 이미 저장된 새 설정을 덮어쓰지 않습니다. GPS·대리/탁송 선택·오늘/내일·감지 상태도 유지합니다. 기존 탁송 판별과 날짜 판별 자체를 새로 변경한 것은 아닙니다.

1. ZIP을 **C:EUNORA-SET6** 같은 짧은 일반 폴더에 풉니다. OneDrive 연결 폴더는 피합니다.
2. `Apply-EUNORA-All.cmd`를 실행하고 아래 프로젝트 경로를 입력합니다.

   `C:Usershjk01AndroidStudioProjectsWheelProbe`

3. 적용 완료 후 Android Studio에서 빌드합니다. **기존 EUNORA 앱을 삭제하거나 데이터를 지우지 말고 업데이트 설치**해야 기존 설정이 이동됩니다.
4. EUNORA를 열어 두 종류의 SET과 기존 설정을 확인합니다. 설치 후 휴대폰을 한 번 재부팅하면 대상 앱들이 새 모듈을 함께 불러옵니다. 재부팅하지 않을 때는 사용 중인 대상 앱들을 모두 강제 종료한 뒤 다시 실행해야 합니다.

이번 기능 변경은 MainActivity.kt, CallMatcher.kt, ConditionProvider.kt, ConditionClient.kt, ConditionBridgeReceiver.kt 다섯 파일입니다. 자동 적용에는 MainActivity의 화면 변경도 포함됩니다. 기존에 앞선 수정을 적용하지 않았어도, 확인된 기존 소스 버전이면 누적 수정이 함께 적용됩니다.

적용기는 전체 내용을 먼저 검증하고 변경 파일을 백업합니다. 임의로 수정된 파일이면 아무것도 쓰기 전에 멈춥니다. 이미 적용된 상태에서는 재수정·중복 백업을 하지 않습니다. 쓰기 중 오류가 나면 이전 파일로 복구합니다. `Unrecognized local file`이 나오면 검사를 지우지 말고 해당 로컬 파일을 대조해야 합니다.

네 개 새 공통 파일의 TXT는 전체 코드입니다. MainActivity는 기존 파일의 화면 부분만 자동 적용하며, `MainActivity-UI.patch`로 변경 부분을 읽어 볼 수 있습니다. TXT 네 개만 복사해서는 화면 변경까지 적용되지 않으므로 이번에는 CMD 자동 적용을 권장합니다.
