# 기존 EUNORA 보안 코드 읽기 점검

2026-11-18에 보관 중인 WheelProbe 소스를 읽어 확인한 내용입니다. 이 점검에서는 기존 Android 파일을 수정하지 않았습니다. 사용자의 현재 PC 소스 전체나 실제 훅 실행을 확인한 결과는 아닙니다.

## 카카오 E02

| 구분 | 코드에 있는 처리 |
|---|---|
| 실제 값 변경 | 특정 파일 존재 결과 false, 루팅 상태 Boolean 변경, 일부 판정 객체의 Boolean·List 변경, 후킹 보고서 List 변경 |
| SDK 설정 변경 | Sentry의 enableRootCheck를 false로 설정 |
| 로그만 기록 | 스캔, 출근 DTO·진입, Integrity DTO·획득·헤더, 정책, 루팅 안내창의 일부 콜백 |
| 조건부 변경 시도 | 응답 본문 문자열 치환, 인자의 특정 이름 Boolean 필드 변경. 실제 객체 구조와 이름에 맞아야 적용됨 |
| 미연결 정의 | clearIntegrityToken은 정의 외 호출 없음. KakaoHookReportMapHooker는 정의 외 등록 참조 없음 |

ModuleMain에서 보안 설치 함수로 연결돼 있지만, 설치를 시도하는 모든 대상의 원형과 실제 실행 성공이 확인된 것은 아닙니다. 일부 로그에 `bypassed`가 있어도 해당 콜백이 결과를 변경하거나 실행을 생략하는지는 별도로 구분해야 합니다.

## L의 새 생성 코드와 구분

L의 관찰 모드는 호출을 기록하고 원래 값과 예외를 유지합니다. Boolean false 모드는 정상 Boolean 반환값을 바꾸고, void 실행 생략 모드는 선택한 본문을 실행하지 않습니다. 기존 EUNORA의 로그 전용 콜백 전체를 자동으로 교체하는 작업은 이번 변경에 포함하지 않았습니다.

이번 변경은 L 생성기의 Debug/Release 실행 제한 제거입니다. APK·메서드·모듈 신원·원본 해시 검증은 유지하며 기존 Android 원본은 보존합니다.
